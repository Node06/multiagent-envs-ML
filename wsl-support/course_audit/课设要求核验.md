# 课设要求与原环境核验

依据：项目中的 `Lecture 16 - Course design (1).pptx` 第5～8页，以及教师原 README。原文件保持当前仓库基线 ca0f9ab 不变，扩展只写入 wsl-support 与团队入口。

## 场景与障碍物

- PPT 第5页：输入环境图像，输出二维有界加速度；目标为避障、避猎人、到达 shelter。随机的是 prey、predator、shelter 三个位置。
- 原 README 的“要求”明确写“障碍物位置固定”，并说明考核会公布两球与目标的初始位置。
- 因此：训练和自测随机采样两球与目标，考核接受老师提供的位置；主测试维持原三障碍的位置及半径。没有证据表明课程要求我们随机生成障碍布局。
- 随机三障碍布局只作为额外压力测试，单独报告，不与考核分布合并。新建场景必须非重叠、保持原障碍数量和边界规则。

## 机器学习与图像输入

- 第6页明确要求至少一种机器学习技术，并学习能够安全控制猎物的模型；原 README 的“或者其他方法”不足以推翻 PPT 的这一明确要求。此前将纯 MPC 作为可直接提交的主方案，需要更正。
- 第7页要求 learned model 输入图像，并完成三个目标。第8页说明 model 需要环境状态输入会扣30分。
- 新主接口是 `LearnedController.act(rgb)`：训练过的 CNN 做语义图像识别，内部计算视觉位置/速度，再由训练过的 Actor 输出加速度。既不接收 env 对象，也不接收 true state、初始坐标或目标坐标。
- 中间仍存在由图像计算的结构化视觉特征；这是分阶段训练的图像管线，不能宣称整条链条是可微端到端训练。若老师把任何内部视觉坐标特征也认定为“state”，需要向老师确认；模型对外输入是 RGB，源码、报告必须透明描述该结构，不保证具体评分。
- ground truth 只用于结果判定和定位误差统计；CNN 监督标签来自图像分割，不来自仿真真实坐标。

## 猎人行为

- 原 environment.py 每次物理推进后，计算 `prey_position-hunter_position` 的单位向量，作为下一步猎人加速度。没有逃离猎物的目标或人为避让条件。
- 原 core.py 的速度惯性、障碍接触力会使瞬时运动方向偏离加速度方向；看到红球绕开/远离绿球，不能推断其控制目标在躲避。
- 诊断中，固定障碍与随机障碍各100个初始图像：两球、目标和障碍的最大位置误差均小于1像素。
- 静止猎物实验：原猎人在第29步捕获；排队加速度与猎物相对位置的余弦最小值1.0。原代码未变。
- 动态评估另记录猎人加速度对齐、猎人接触障碍帧数，以及未接触障碍的成功案例。利用原环境障碍力不构成改规则，但“猎人接触障碍”与成功的关联不能直接当作因果证明。

## 算法选择

纯 PPO 旧独立测试仅12/60成功，不能声称它已经是最合适的算法。PPO 适合已有连续 Actor-Critic 实现，但 CPU 图像交互昂贵且稀疏失败事件难探索。

本次采用 CNN 感知训练 → MPC 示范预训练 → DAgger → 带示范正则的 PPO 微调。MPC 只提供训练标签与评测基线，不在主模型运行时生成动作。分别冻结模仿学习与最终选模检查点，检验 PPO 是否实际改善；如果未改善，报告必须说明，不能把示范阶段收益归给 PPO。

SAC 的经验回放可提高数据利用率，但本项目尚无同预算 SAC 实验，所以不会宣称 PPO 优于 SAC。方法依据：[PPO](https://arxiv.org/abs/1707.06347)、[DAgger](https://www.ri.cmu.edu/pub_files/2011/4/Ross-AISTATS11-NoRegret.pdf)、[SAC](https://arxiv.org/abs/1812.05905)。
