# 视觉识别、全局路径规划与 MPC 动态避追：项目实现方案

本文保留最初实施设计。当前已实现控制器、可视化、评测与报告，程序位于 `wsl-support/vision_mpc/`。该目录 `README.md` 记录最终实现与设计差异；正式 100 场测试和额外 8 场压力测试分开保存。以下尚未实现的扩展（例如持续遮挡预测、CNN、PPO/SAC 对照）不计入已完成成果。现有 WSL2 Ubuntu-22.04、Python 3.10 环境可直接运行，保留老师原有程序。

## 1. 任务边界与评分目标

依据项目 `readme.md`：通过深度学习或其他方法，使被追击者避开追击者和固定障碍物并到达目标；状态输入必须来自图像；考核时提供追击者、被追击者和目标的初始位置。初始化参数用于创建考核场景，不代替图像检测结果输入控制器。

评分为图像输入 30、规避障碍 20、规避猎手 10、到达目的地 20、汇报 20。主方案选择“颜色识别 + A* 全局规划 + 采样/束搜索 MPC”。MPC 在此指滚动预测并执行首个动作，不要求使用复杂的非线性优化器。

主方案不训练神经网络。课程的强化学习案例用于对照和讨论，不能将本方案描述为 PPO、SAC 或深度学习。README 允许其他方法；若老师另有必须使用学习算法的要求，需要调整主方案。

### 评分与证据

| 项目 | 方法 | 展示与实验凭据 |
|---|---|---|
| 图像输入 30 | RGB 图像分割、连通域定位、多帧速度估计 | 原始图像与检测叠加图；图像来源审计；漏检统计 |
| 避障 20 | 障碍膨胀、全局绕行、预测轨迹安全检查 | 障碍碰撞率、轨迹与障碍间距 |
| 避猎手 10 | 猎手轨迹预测、危险距离与最小风险动作选择 | 被捕率、追击预测图、典型逃脱与失败案例 |
| 到达 20 | 目标引导与全局路线、卡住后的重规划 | 到达成功率、成功回合步数、超时率 |

## 2. 已核实的代码行为

1. `demo.py` 用共享窗口显示两个智能体。红球自动追击，绿球接受五维动作；它不是键盘交互程序。
2. `env.render("rgb_array")` 返回图像列表，共享窗口应取 `[0]`。图像是 RGB、800×800；OpenCV 颜色转换需要使用 RGB 对应的转换常量。
3. `env.reset(...)` 返回两个智能体的观测列表，并非标准 Gymnasium 的 `(observation, info)`。
4. `env.step(action)` 返回 `(obs_n, reward_n, done_n, info_n)`。控制器不用其中的真实状态观测。
5. `environment.py` 在设置当前动作之前调用 `world.step()`：当前提交的动作下一次调用才参与运动，存在一步延迟。
6. `simple_tag.py` 中绿球撞障碍或到达目标都会结束；红球捕获绿球也会结束。`done=True` 不等于成功。
7. 当前 `ppo.py` 默认进入旧模型加载流程；其成功统计不能直接沿用。
8. `core.py` 的时间步为 0.1，速度更新后再更新位置；阻尼处理被注释。动作是加速度控制，“不施加动作”不会立即停车。
9. 绿球与红球半径均为 0.025，最大速度分别为 0.25、0.28，加速度系数分别为 1.0、0.85。目标结束阈值为中心距离小于 0.075，障碍结束阈值为中心距离不大于 0.075。
10. 原 `reset_world()` 没有显式清空已排队的运动动作。为避免上一回合的动作影响新回合，实验初版每回合重建 world/env；不暗中修改老师的运动规则。

默认保留原有动作时序、追击规则、速度、障碍和结束规则。若以后修改环境，须单列修改版实验，不能与原环境结果混报。

## 3. 文件组织与模块接口

所有新增项目程序放在同一个扩展目录中：

```text
wsl-support/

    global_planner.py           # 占用栅格、A*、路线简化
    dynamics.py                 # 自有预测模型，不读取真实状态
    controller.py               # MPC 候选、预测、代价、安全检查
    env_adapter.py              # 创建场景、动作转换、接口适配
    evaluator.py                # 终止分类、统计
    run.py                      # 命令行运行入口
    visualize.py                # 检测与规划叠加图、视频
    tests/                      # 核心几何、时序与指标验证
    outputs/
      calibration/              # 视觉与预测验证
      validation/               # 参数选择
      test/                     # 固定测试集的最终结果
```

接口建议：

```python
detection = perception.detect(rgb_image)
state = estimator.update(detection, dt=0.1)
route = planner.plan(state, map_config)
command, debug = controller.choose_action(state, route, pending_action)
action5 = adapter.to_action5(command)
obs_n, reward_n, done_n, info_n = env.step(action5)
```

`state` 包含：红/绿球中心和估计速度、目标中心、障碍中心与半径、可见边界、每类检测有效性与估计误差。`pending_action` 是控制器自己上一步提交的动作，不是环境隐藏状态。

控制器模块只能接收图像推导状态、公开的固定物理参数和自己提交过的动作。禁止给控制器传入 `world.agents[*].state`、`obs_n`、预先保存的真实轨迹或初始化真实坐标。

## 4. 图像识别与速度估计

### 4.1 识别对象

分别建立红球、绿球、紫色目标、黑色障碍的颜色掩码。建议在 HSV 空间分割，红色跨色相边界时合并两段范围；保留 RGB 分割作为对照。不要直接套用 BGR 阈值。

对掩码执行连通域分析，结合面积、长宽比、位置和上一帧结果筛选；必要时轻量形态学处理。红色边框必须与红球区分，黑色对象应排除背景和其他类别。

用有效像素的质心估计中心，用面积/轮廓估计物体尺度。障碍采用固定空间顺序标识，例如按横坐标再纵坐标排序，不随“离绿球最近”改变编号。每个回合从图像检测障碍地图，不在控制器中硬编码 README 的障碍坐标。

### 4.2 坐标转换

图像已上下翻转为通常的左上角原点。若像素中心为 `(u, v)`，宽高为 W、H，则世界坐标近似为：

```text
x = 2 × (u + 0.5) / W - 1
y = 1 - 2 × (v + 0.5) / H
```

通过测试图验证左右、上下方向，避免将逃离猎手变成靠近猎手。800 像素对应跨度 2，一个像素约为 0.0025 世界单位。

### 4.3 速度、遮挡和异常

连续位置差除以 0.1 估计速度，可用最近 3～5 帧拟合或指数平滑减少像素噪声。初始速度设为零并标记低置信度；不能在第一帧差分。

漏检一两帧时短暂使用预测，增加不确定性安全距离。连续漏检时进入异常/最小风险模式并记录，不允许对空像素集合求均值产生 NaN。两球接近、红球靠边、部分遮挡必须作为专项测试。

验收目标：正常非遮挡帧的对象检测成功率至少 99%，人工标注中心误差以 2 像素以内为初始目标；这只是待验证目标，不能当作已取得的结果。人工标注和内部真值对比仅用于独立诊断，不能作为在线决策输入。

## 5. A* 全局规划

### 5.1 静态地图与安全范围

用检测结果建立栅格，初始分辨率可取 0.02 世界单位，约 100×100。八邻域搜索，禁止对角穿越障碍角点。

障碍的禁止范围按“障碍半径 + 绿球半径 + 视觉/跟踪误差裕量”膨胀。例如 0.05 + 0.025 + 0.015 = 0.09；0.015 为调参起点，过大会封死通道，过小会增加碰撞。

边框的显示形状与物理碰撞形状不是完全等价的：显示为方块，物理碰撞使用实体半径。不能简单把白色区域全当作可安全进入区域。通过边界诊断，校准保守可行范围，并把校准依据写入报告。

目标可选为其到达区域内的可行栅格，不因栅格取整要求必须经过目标中心。对目标靠近障碍的情况，检查到达区域内是否仍有可行点。

### 5.2 路线与重规划

A* 提供绕障拓扑路线，不直接把栅格拐点作为瞬时速度指令。简化路线时对整段检查膨胀障碍碰撞，选择前视路径点供 MPC 跟踪。

红球是动态对象，不永久写成静态禁止区。初版由 MPC 避追；若发现全局路线长期通向红球所在一侧，再加入有时间期限的猎手风险代价和替代绕行路线。

初版每 10 步或出现明显偏离/卡住时重规划；猎手接近时可提前重规划。无路线应记录原因，不能无限调用规划器而不执行控制。不要把“几何上有路线”当成“在猎手追击下必定能成功”。

## 6. 动力学预测与一步延迟

### 6.1 自有预测模型

不调用真实环境试走候选轨迹，也不读取内部真实坐标。预测在自己的数组模型中进行：

```text
v_next = clip_speed(v + acceleration × dt, max_speed)
p_next = p + v_next × dt
```

绿球加速度由候选动作和系数 1.0 得到。红球加速度按其预测位置指向绿球的预测位置，系数 0.85。接近零距离时使用 epsilon 防止除零。

以上是无碰撞区的模型。候选绿球轨迹发生危险接近时剔除，不依赖撞击反弹作为导航；红球被障碍偏转时预测误差会变大。初版用安全裕量与每步重估处理，后续可补充从 `core.py` 公式复现的碰撞模型，或比较“追逐方向预测”和“短期匀速预测”的保守风险包络。

### 6.2 时序必须与老师环境一致

在时刻 t 看到图像并提交动作 a_t 后，下一幅图像仍主要反映先前排队的 a_(t-1)。因此预测状态中必须包含排队动作：

1. 第一个预测步使用上次提交的绿球动作。
2. 后续预测步才使用当前候选序列的动作。
3. 红球追击动作按原代码“运动后计算，下一步执行”的顺序预测。
4. 每回合重建环境以获得清楚的初始动作状态。

红球当前排队加速度可用上次图像中的红/绿位置按追击规则推算；启动首步按新环境动作状态处理。不要为使预测更容易而静默把真实环境的 `world.step()` 移到设置动作之后。

验收：在远离碰撞的片段执行固定动作和反向动作，比较图像估计的下一步位置与预测值；分别验证 x/y 方向、速度上限和动作延迟。报告一步误差和多步误差，而不是声称精确预测所有碰撞。

## 7. MPC 动态避追控制

### 7.1 动作集合与 CPU 预算

初始候选为 8 个方向，力度取 0.5 与 1.0，再加零加速度，共 17 个动作；对角方向先归一化。额外允许当前速度反向的制动候选，以便减速。

搜索初版采用束搜索：预测长度 H=20（约 2 秒），束宽 B=16。按每层保留低代价候选限制分支数，避免完整枚举 17^20。这些数值是起点，需测试 15/20/30 步与不同束宽的成功率和每步耗时。Python 实现优先使用 NumPy 批量预测。

MPC 每次只执行最优序列首个动作，收到新图像后重新预测。不把整条预测序列直接连续执行，否则不能及时适应猎手变化。

### 7.2 安全检查

对预测轨迹的相邻位置做线段/扫掠距离检查，不只检查离散端点。绿球与猎手的相对轨迹同样需要检查，避免两步之间相撞。

绿球距离障碍小于膨胀半径的序列剔除；猎手距离低于两球半径之和加不确定性裕量的序列优先剔除。预测误差越大或猎手越接近，裕量越保守。

如果没有满足全部安全约束的序列，不假设零动作就能停车。进入明确的最小风险退路：比较制动、远离猎手和回到可行区域的动作，并记录 `no_safe_candidate`。已无可避免的失败不能通过更改终止条件掩盖。

### 7.3 代价设计

先使用安全约束，再在安全候选中比较以下归一化代价：

```text
J = w_path × 偏离全局路线
  + w_goal × 沿路线剩余距离
  + w_hunter × 猎手危险接近程度
  + w_obstacle × 障碍/边界低间距风险
  + w_action × 动作变化
  + w_terminal × 预测末端剩余路线距离
```

“剩余距离”优先用绕障路线距离，不能只用到目标的直线距离，否则可能因隔着障碍而停在错误一侧。猎手风险可以用距离与预计接近时间共同描述，但避免直接把距离倒数在零点计算。

所有项先统一尺度再调权重。目标附近适当重视制动和进入到达区域；不能以无限逃跑、反复绕圈换取看似低碰撞率。

### 7.4 五维动作映射

若二维命令 q=(qx,qy)，每维范围 [-1,1]，则转换为：

```text
[noop, right, left, up, down]
= [0, max(qx,0), max(-qx,0), max(qy,0), max(-qy,0)]
```

零加速度可用 `[1,0,0,0,0]`，但它不是立即停止。使用原有浮点向量接口，不切换到其整数动作分支；两种分支的方向定义存在差异。验收必须用实测移动方向确认。

## 8. 开发顺序与进入下一阶段的标准

| 阶段 | 工作范围 | 交付物 | 验收后才继续 |
|---|---|---|---|
| A：接口与时序 | 独立扩展目录、创建场景、记录动作、区分结束 | 能运行的基础入口、时序说明 | 与原 demo 运动方向和动作延迟一致 |

时间应先用小规模运行测量再估算，不能根据 CPU 型号承诺训练或调试天数。若进度紧张，优先完成 B、C、E 和准确评估，CNN/PPO/SAC 对照属于扩展工作。

## 9. 公平评估与成功率

### 9.1 场景分组

固定三组互不重复的初始化清单：校准场景、调参验证场景、最终测试场景。初版可使用约 50 个验证场景、100 个测试场景，再按时间扩展。这些数量是实验设计建议。

测试覆盖：无障碍直达、目标在障碍另一侧、通道附近、猎手位于通往目标的方向、猎手在身后、靠边起点、靠边目标、较近追击、多种红绿相对方位。抽样拒绝初始重叠和越界，但不因为方案失败就删除合法难场景。

当前红球速度上限大于绿球，一些合法初始位置可能本就很难成功；保持这些场景并单列分析，不声称百分之百可达。

### 9.2 结束分类

记录 `success`、`caught`、`obstacle_collision`、`timeout`、`perception_failure`、`ambiguous_terminal`。同时发生成功与碰撞时，保守优先记录失败，并说明口径。

原代码没有提供完整原因字段：红球 done 可辅助判断被捕；绿球 done 还需区分到达与障碍。在线状态由图像判断，结束原因模糊时不要算成功。必要时用独立离线评估器读取环境真值核对原因；该评估器只在决策后记录指标，不能把真实位置传回控制器，且需确认老师允许这种实验诊断。

边界碰撞在 README 中不属于障碍终止，因此单独记录边界接近/接触，不暗中更改正式终止规则。初版回合上限可取 500 步，所有方案一致；不同上限需要单列结果。

### 9.3 输出指标

```text
成功率 = 成功回合数 / 总合法测试回合数
被捕率 = 被捕回合数 / 总合法测试回合数
障碍碰撞率 = 障碍碰撞回合数 / 总合法测试回合数
超时率 = 超时回合数 / 总合法测试回合数
```

成功步数仅对成功回合统计，并同时报告成功回合数；不能用平均步数掩盖低成功率。另记录检测失败数、最小猎手间距、最小障碍间距、无安全候选次数、每步决策耗时的中位数/95 分位数和完整端到端耗时。

初始性能目标为端到端每步 0.1 秒以内，以匹配 10 Hz 模拟控制；正式验收以实测为准。演示可另用 10～30 FPS 播放，不能把播放帧率当作决策性能。

各方案使用同一批初始化案例，报告成功率和二项比例置信区间；若增加强化学习对照，至少比较多个训练随机种子。最终测试后再调参则需要新测试集。

## 10. 对照、消融与汇报

对照一：朝目标运动，不主动避障/避追。
对照二：图像 + A* 跟踪，缺少猎手预测。
主方案：图像 + A* + MPC，包含猎手预测与一步延迟。
消融一：主方案去掉猎手预测，仅用当前距离风险。
消融二：主方案不补偿动作延迟。
可选扩展：修正统计与接口后的图像特征 PPO 或 SAC。

只在同一原环境中比较正式成绩。若为诊断暂时移除猎手、改变速度或重新排列 step，结果必须标记为诊断环境，不能混入正式成功率。

汇报应说明：评分要求与数据来源；颜色检测与图像速度估计；全局绕障与局部预测控制的分工；延迟与惯性；公平测试和消融；典型成功及失败案例；算力与局限。重点展示从原始图像到控制动作的证据链。

视频至少包含：识别叠加、绕障到达、猎手阻挡时调整路线、一个失败案例。所有展示案例保留编号和配置，避免只展示最好的一次。
