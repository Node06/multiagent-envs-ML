# 团队交接：先读这份指南

这是老师原项目加已完成的“图像识别 + A* + MPC V2”主方案和“视觉状态 + PPO”学习对照，不需要复制作者的 Linux、虚拟机或 Python 环境。Windows 和 Linux 可以使用同一份 Python 源码；每人按自己的系统建立 Python 3.10 环境并安装共享依赖。已经配好环境的同学先自检，不要直接覆盖自己的环境。

## 1. 我已经做了什么

- 保留老师的运动、追击、物理碰撞与终止规则；修正 setup.py 的安装依赖声明。
- 从真实 RGB 渲染图像识别红球、绿球、目标和障碍；用连续图像估计速度，不向控制器输入内部真实坐标。
- A* 绕障规划、考虑一步动作延迟和惯性的 MPC、猎手预测与 V2 临时避险搜索。
- 保存旧版 V1：V2 在预测危险时允许先远离目标，再返回目标，没有针对具体案例 ID 编写特例。
- 批量配对测试、统计成功/被捕/撞障碍、标注显示、录像、失败回放、报告和汇报提纲。
- 测试结果：原分层 V1 118/120、V2 回归 120/120；普通回归 100/100；新独立测试 V1 59/60、V2 60/60。不同数据用途分开报告，不能保证任意位置必胜。

原 `demo.py` 仍是固定动作演示；MPC 主方案入口是 `wsl-support/vision_mpc/run.py`。原根目录 `ppo.py` 是老师参考代码；此次完成的 PPO 在 `wsl-support/vision_ppo/`，使用 21 维图像估计状态、有界高斯策略、GAE、超时自举、课程学习和验证集选模型。

PPO 三个种子各训练 131072 步，合计 393216 步。在另一批 60 个新场景上，A* 为 36/60，原版 MPC 为 60/60，PPO 三个种子为 12/60、7/60、3/60。该批 PPO 对照与上面的 MPC V2 独立测试不是同一批位置，不能混合计算。PPO 已完成代码与固定预算实验，成功率尚低，未达到替代 MPC 的水平。

MPC 不用 PyTorch、CUDA或训练模型。PPO 需要 PyTorch，但本次采用 CPU，包中已包含模型，可直接推理，无需先重新训练。

## 3. Windows 同学怎么运行

不要求改用 Linux。先打开 PowerShell/Anaconda Prompt，进入解压后的项目主目录。

### 方案 A：已有 Conda，推荐

```powershell
conda env create -f wsl-support/team-share/environment-team.yml
conda activate multiagent-ml
python -m pip install --no-build-isolation -e .
python wsl-support/team-share/check_environment.py
python wsl-support/vision_mpc/run.py --mode demo --show --video --realtime
```

如果已经有同名环境，不要覆盖原有工作：可以把 YAML 中 name 改为 `multiagent-team`，并激活这个新名称。已有可用 Python 3.10 项目环境的同学也可以直接执行第 5 节的共享安装命令。

### 方案 B：已有官方 Python 3.10，使用 venv

```powershell
py -3.10 -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip "setuptools<81" wheel
.venv\Scripts\python.exe -m pip install -r wsl-support/team-share/requirements-team.txt
.venv\Scripts\python.exe -m pip install --no-build-isolation -e .
.venv\Scripts\python.exe wsl-support/team-share/check_environment.py
.venv\Scripts\python.exe wsl-support/vision_mpc/run.py --mode demo --show --video --realtime
```

这种写法不需要执行 Activate.ps1，避免 PowerShell 脚本执行策略问题。
使用本地 `.venv` 的同学可直接双击 `RunWindows.cmd`；使用 Conda 的同学应从已激活的终端运行该 cmd 或直接运行 Python 命令，否则双击可能用到 base 的错误 Python。

## 4. Linux/WSL 同学怎么运行

已装 Conda 可使用同一 environment-team.yml，然后执行可编辑安装与自检。若使用 Ubuntu 22.04 的 Python 3.10：

```bash
sudo apt-get update
sudo apt-get install -y python3-venv libglu1-mesa libgl1 libglib2.0-0
python3 --version                       # 需要 3.10，不是 3.12/3.14
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip "setuptools<81" wheel
python -m pip install -r wsl-support/team-share/requirements-team.txt
python -m pip install --no-build-isolation -e .
python wsl-support/team-share/check_environment.py
bash wsl-support/vision_mpc/run_linux.sh
```

WSL 需要能打开图形窗口的 WSLg，普通 Linux 需要可用桌面/显示服务。纯无显示服务器不能直接使用当前渲染方式。
新 launcher 从自身位置找到项目目录，没有写死 `/mnt/e/...`。目录可以不同，但命令必须在项目主目录执行。

## 5. 为什么统一 Python 3.10 和依赖

老师的 scenarios 加载器使用 `imp`，Python 3.12 已删除它，所以直接用 3.13/3.14 会失败。先统一到 3.10，不必全组同时迁移老师代码。

如果已经激活 Python 3.10 环境，安装命令就是：

```bash
python -m pip install --upgrade pip "setuptools<81" wheel
python -m pip install -r wsl-support/team-share/requirements-team.txt
python -m pip install --no-build-isolation -e .
python -m pip check
```

不要拿作者的 `requirements-wsl.lock.txt` 在 Windows 上安装，其中可能有本机路径和平台依赖。
操作系统、显卡驱动、DPI 与图形后端可能导致像素、速度和结果细微差异，固定 Python 依赖不等于保证全机结果逐字一致。

## 6. 自检与当前验证范围

```bash
python wsl-support/team-share/check_environment.py
python -m unittest discover -s wsl-support/vision_mpc/tests -v
```

自检成功应打印 PASS，并在 team-share 目录生成 `platform_check.png`。只用 `--packages-only` 只检查包版本，没有检查图形渲染。

当前完整追逃与大批量评测、以及新的交接自检脚本，已在作者的 WSL2 Ubuntu-22.04 验证；原生 Windows 的新入口是按跨平台代码准备的，尚未完成原生 Windows 实机渲染验证。请先自检和默认场景，再运行考核位置，不要直接假设 Windows 必然重现所有统计。

若 Windows 出现 OpenGL/窗口错误，先确认显卡驱动、远程桌面环境以及缩放；不要升级到 Pyglet 2.x 来试错，老渲染代码依赖 1.5 API。自检若发现帧尺寸不是 800×800，应先记录 DPI/显示设置，不要改世界尺度。

## 7. 自定义位置、测试与录像

```bash
python wsl-support/vision_mpc/run.py --hunter 0.3 0.1 --evader -0.6 0.5 --goal 0.6 -0.6 --show --video --realtime
python wsl-support/vision_mpc/run.py --mode compare --methods mpc_v1 mpc --count 20 --seed 12345
```

按 Esc 关闭标注窗口，或 Ctrl+C 停止。结果自动存到 vision_mpc/outputs；其中 cases.json、config.json 和 results.csv 必须一起保留。
复现历史 V1 带 mpc 标签的数据，应增加 `--controller-version v1`。不要把 V1 的 no_hunter/no_delay 消融当成 V2 的消融。

## 8. 在原基础上继续优化怎么分工

| 工作 | 主要文件 | 检查重点 |
|---|---|---|
| 图像识别/速度估计 | perception.py、state_estimator.py | 漏检、遮挡、坐标方向、定位误差 |
| 全局路径 | global_planner.py、geometry.py | 障碍膨胀、无路、边缘目标、通道 |
| 动态避追 | controller_v2.py、dynamics.py | 候选覆盖、预测误差、成功率与开销 |
| 评测/汇报 | evaluator.py、run.py、各 report.py | 成功与碰撞区分、配对场景、测试泄漏 |

建议先用 Git 保存本包为基线，每人单独分支；如果暂时不用 Git，也至少复制一份带版本名的基线，别互相覆盖整文件夹。
每次修改记录改动文件、参数和理由；用同一批验证场景比较，保留旧版 controller_v1.py。已用来优化的案例是开发/验证数据，最终效果必须用新的独立场景评估。
原 core.py、environment.py、simple_tag.py 是老师规则；除非全组明确决定并单列实验，不要直接改变速度、猎手行为或成功阈值来提高分数。

发回组内的改动应包含源码差异、config.json、cases.json、results.csv、结论和至少一个失败/代表案例，不要只发最好的一段视频。

PPO 可分工：一人修改 rewards.py 与训练场景课程；一人修改 model.py/ppo.py；一人负责独立评测与误差分析。MPC 与 PPO 尽量共用 perception.py、state_estimator.py 和相同初始场景，避免把感知差异误当作控制算法差异。已有 holdout 的结果已经公开，继续用它优化后，它就成为回归/开发数据；最终结论应另生成新的独立测试位置。

## 10. PPO：Windows 和 Linux 的共同入口

先按第3或第4节装好基础依赖。再安装 CPU PyTorch（不需要 NVIDIA 显卡）：

```bash
python -m pip install -r wsl-support/team-share/requirements-ppo.txt --index-url https://download.pytorch.org/whl/cpu
python -m pip check
python team_run.py check --ppo
python team_run.py tests
```

使用 Windows venv 且未激活的同学，将上面的 `python` 替换成 `.venv\Scripts\python.exe`；例如：

```powershell
.venv\Scripts\python.exe -m pip install -r wsl-support/team-share/requirements-ppo.txt --index-url https://download.pytorch.org/whl/cpu
.venv\Scripts\python.exe team_run.py check --ppo
.venv\Scripts\python.exe team_run.py ppo --show
```

激活环境后，Windows PowerShell、Conda Prompt、Linux/WSL 均可执行下面的单行命令：

```bash
python team_run.py mpc --show --video --realtime
python team_run.py ppo --show
python team_run.py train --seed 41 --steps 8192 --output wsl-support/vision_ppo/outputs/team_short_seed41
python team_run.py train --seed 41 --steps 131072 --output wsl-support/vision_ppo/outputs/team_seed41
python team_run.py evaluate --checkpoints wsl-support/vision_ppo/outputs/formal_20261013/seed11/best.pt --cases wsl-support/vision_ppo/outputs/formal_20261013/holdout/cases.json --baselines astar mpc_v1 --output wsl-support/vision_ppo/outputs/team_retest
```

不要把短程训练结果当成最终效果；每次使用新的输出目录。三个种子完整训练可调用 `vision_ppo/run_experiment.py`，CPU 训练较耗时。本机首次正式训练约一小时，别人的电脑用时会不同。

Windows 同学可双击项目根目录的 Run_MPC_Windows.cmd / Run_PPO_Windows.cmd（venv 会自动寻找；Conda 需先从已激活的终端运行）。不要双击旧 RunPPO.cmd，它是作者机器的 WSL 入口，共享包已排除。

PPO 默认场景在当前模型下第171步撞障碍，属于已记录的失败演示。成功案例视频位于 `vision_ppo/outputs/formal_20261013/representative_replays/ppo_seed11_s6101399_001.mp4`。模型优先按解压后的本地路径寻找，旧 JSON 中的作者绝对路径仅作历史审计记录，不依赖你的磁盘与目录名称。
